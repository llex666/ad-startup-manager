# AD Startup Manager

Интерактивная консольная утилита на PowerShell (меню в стиле `sconfig`) для **просмотра, включения, отключения и удаления элементов автозагрузки** на всех компьютерах домена Active Directory — пользовательских ПК, серверах и виртуальных машинах.

> [English version](README.en.md)

## Что считается автозагрузкой

| Источник | Что проверяется |
|----------|-----------------|
| Реестр `Run` | `HKLM\...\Run`, `HKLM\...\WOW6432Node\...\Run` (x86) и `HKU\<SID>\...\Run` **всех профилей** пользователей (незагруженные `NTUSER.DAT` временно подключаются) |
| Папки Startup | общая (`ProgramData`) и папки всех профилей |
| Планировщик | задания с триггером «при входе» / «при загрузке» (системные `\Microsoft\*` по умолчанию скрыты) |

Не проверяются: `RunOnce`, службы, драйверы, `Winlogon`/`Shell`, WMI-подписки и другие механизмы закрепления.

## Возможности

- **Включение, отключение и удаление** элементов автозагрузки. Для реестра и папок включение/отключение выполняется так же, как в Диспетчере задач (ключи `StartupApproved`), для заданий — `Enable/Disable-ScheduledTask`.
- Раздельные таблицы: **компьютеры пользователей** и **серверы / ВМ** (по `OperatingSystem` в AD).
- Выбор, что сканировать: все / только пользовательские / только серверы, а также **отдельные OU** (с вложенными). Результаты нескольких сканирований накапливаются.
- **Индикатор выполнения** и прерывание по `Esc`.
- Сводка «элемент → на скольких компьютерах», с числом отключённых.
- Действие **по имени** над всеми или выбранными компьютерами; выбор отдельных строк в `Out-GridView`.
- Подтверждение `YES` для удаления, лог (команда удалённого элемента сохраняется), экспорт в CSV, список недоступных компьютеров.

## Требования

- Windows PowerShell 5.1 (PowerShell 7 не проверялось).
- Модуль **ActiveDirectory** (RSAT).
- Права администратора на целевых компьютерах.
- На целевых компьютерах включён **WinRM (TCP 5985)** — скрипт выполняется на них через `Invoke-Command`. Резерва через DCOM нет.
- Для выбора строк вручную нужен `Out-GridView`.

## Быстрый старт

```powershell
git clone https://github.com/llex666/ad-startup-manager.git
cd ad-startup-manager

powershell -ExecutionPolicy Bypass -File .\Manage-DomainStartup.ps1
# или
.\Manage-DomainStartup.ps1 -Domain corp.example.com -StaleDays 60
```

Программа **сначала показывает меню**; сканирование запускается пунктом `1`.

## Параметры

| Параметр      | По умолчанию               | Описание                                                     |
|---------------|----------------------------|--------------------------------------------------------------|
| `-Domain`     | `$env:USERDNSDOMAIN`       | DNS-имя домена AD                                            |
| `-StaleDays`  | `90`                       | Пропускать компьютеры, не заходившие в домен более N дней    |

## Меню

```
  Сканирование
   1) Запустить сканирование с текущими параметрами
   2) Тип компьютеров: [все компьютеры]  (нажмите, чтобы переключить)
   3) Область (OU): [весь домен corp.example.com]
   C) Очистить результаты

  Просмотр
   4) Автозагрузка: компьютеры пользователей
   5) Автозагрузка: серверы и виртуальные машины
   6) Сводка (имя → на скольких ПК)
   U) Недоступные компьютеры

  Изменение
   7) Отключить по имени (все / выборочно)
   8) Включить по имени (все / выборочно)
   9) Удалить по имени (все / выборочно)
   G) Выбрать строки (Out-GridView) и применить действие

  Прочее
   T) Задания планировщика (вход/загрузка): показаны
   M) Системные задания \Microsoft\*: скрыты
   E) Экспорт в CSV
   0) Выход
```

Клавиши работают и в русской раскладке.

## Как это работает

1. Список компьютеров берётся из AD с учётом типа, OU и `-StaleDays`.
2. Проверяется порт 5985 (параллельно, пачками по 100).
3. На доступные компьютеры отправляется блок кода через `Invoke-Command -AsJob` (до 32 одновременно); прогресс считается по завершённым дочерним заданиям.
4. Блок на целевом ПК читает реестр, папки Startup и планировщик, а при изменении правит те же источники.
5. Профили пользователей, не загруженные в реестр, временно подключаются через `reg load` и затем отключаются.

## Безопасность и ограничения

- **Удаление необратимо.** Проверьте на пилотной OU. Команда удалённого элемента записывается в лог — по ней запись можно восстановить вручную.
- Лог (`DomainStartupManager.log`) и CSV содержат имена ПК, пользователей и командные строки — не публикуйте их (они в `.gitignore`).
- Профили, у которых `NTUSER.DAT` занят (например, в момент входа пользователя), могут быть пропущены или вернуть ошибку.
- Компьютеры без WinRM попадают в раздел «Недоступные».
- Ответственность за использование лежит на вас (см. лицензию).
